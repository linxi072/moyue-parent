## 二、产品定义

### 2.1 Product Goals（3 个正交目标）

1. **架构目标**：完成 **9 → 12 模块重构**，新增 `moyue-search` / `moyue-message` / `moyue-risk` 三个独立 Maven 模块，服务边界清晰、可独立注册与启动，存量模块依赖不回归。
2. **能力目标**：补齐 P2-13~P2-17 五项能力，形成「可检索 / 可触达 / 可管控 / 可扛量 / 可治理」的完整后端闭环。
3. **可运维目标**：本地无 Nacos / 无 ES 场景下仍可启动验证；敏感配置全部外部化，生产环境零硬编码密钥。

### 2.2 User Stories

1. **作为读者**，我想在书城按关键词 + 分类检索，并能按热度/更新时间排序，以便快速找到想看的书。
2. **作为运营**，我想在首页配置热门推荐位，以便把优质书籍曝光给全体用户。
3. **作为平台系统**，我想在审核通过/被拒/收到私信等事件发生时，通过站内信 + 邮件自动触达用户，并预留短信 / App 推送通道，以便后续接入供应商时无需改动业务代码。
4. **作为内容审核员**，我想让系统先做敏感词与机审自动判定，只把可疑内容推给我人工复核，并让用户举报能形成「举报 → 处理 → 通知」闭环，以便降低人工成本、提升合规性。
5. **作为运维 / SRE**，我想在流量高峰时限流、在下游异常时熔断降级，并让 dev/test/prod 三套环境配置隔离、密钥走环境变量，以便保障线上稳定与安全。

## 四、依赖与约束

### 4.1 已确认决策（必须遵守）

1. **模块重构 = 新增 3 个独立 Maven 模块**：抽出 `moyue-search`（搜索与推荐）、`moyue-message`（消息触达），新建 `moyue-risk`（内容安全）。**9 → 12 模块**。
2. **P2-14 深度**：定义 `ChannelSender` 渠道 SPI；**站内信 + 邮件（JavaMail，SMTP 可配）为真实现**；**短信 / App 推送为可插拔桩实现**（便于后续接入供应商）。
3. **P2-16 选型**：采用 **Sentinel**（Spring Cloud Alibaba）做**限流 + 熔断降级**。
4. **P2-17 落法**：Spring Profiles(dev/test/prod) + 敏感项（JWT / DB 口令）**环境变量化并移除硬编码** + 预留 **Nacos Config 接入开关**（本地无 Nacos 也能启动验证）。

### 4.2 技术约束

- 统一响应体 `R<T>`（code/message/data/traceId，HTTP 统一 200 承载）；网关 JWT 鉴权后向下游注入 `X-User-Id` / `X-User-Role`；`AdminRoleInterceptor` 保护 `/api/v1/admin/**`（role=3）。
- 数据库变更统一走 **Flyway**，新增表（举报表、渠道/模板表等）需纳入版本化迁移脚本。
- 定时任务统一使用 **XXL-Job 2.4.0**，不引入第二套调度框架。
- 新增模块须遵循现有分层（controller / service / mapper / entity）与包命名规范。

### 4.3 外部依赖

- MySQL、Redis、Nacos、Elasticsearch：本地以 docker-compose 提供（ES 服务需补齐）。
- SMTP 服务：本地可用 MailHog / mock SMTP 验证邮件真实现。
- 短信 / App 推送供应商：本次不接入，仅桩实现。

### 4.4 非目标（Out of Scope）

- 前端 / UI 改动（纯后端迭代）。
- 短信与 App 推送的真实供应商接入。
- 竞品分析（按需求约定本次不做）。
- Nacos Config 的全面落地（仅预留开关）。
- 配置加密 / 密钥轮换（列为 P2）。
