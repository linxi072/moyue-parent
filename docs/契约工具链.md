# 墨阅小说网 · 接入契约工具链设计（springdoc-openapi + 前端代码生成）

> 🗑️ **已废弃（单体化后）**：本文描述的 `moyue-contract` 模块与按服务拆分的 OpenAPI 聚合，在单体化重构中已删除。单体后端为单个 `moyue-app`，前端直接调用 `/api/v1`（见 `moyue-frontend/vite.config.ts` 代理与 `src/api/sample/base.ts` 的 `BASE_PATH`）。如未来需重新生成前端 TS 客户端，请基于单模块的 springdoc `/v3/api-docs` 重新设计，而非本文的多服务聚合方案。

> 适用范围：墨阅小说网多模块微服务项目（Spring Boot 3.2.12 / Java 17）。
> 目标：在不依赖运行中的 MySQL/Redis/Nacos（单体已移除）/ES 集群的前提下，让**每个对外暴露 REST 的服务**自动产出高质量 OpenAPI 规范，在 `com.moyue.system` 一处聚合所有服务的 swagger-ui，并用静态 sample spec 跑通前端 TypeScript 客户端生成链路。
> 约束来源：`docs/不可忽视条件.md`（禁用 Docker；dev 环境不保证中间件在运行；设计必须经 `mvn compile` 验证）。

## 0. 现状核实（已读源码确认）

| 项 | 现状 | 结论 |
|---|---|---|

## 1. 哪些模块接 springdoc（二选一结论）

**结论：方案 B —— 网关不接 springdoc，统一在 `com.moyue.system` 聚合。**

| 模块 | 技术栈 | 是否接 springdoc | 接入依赖 |
|---|---|---|---|
| com.moyue.auth (8090) | Spring MVC | ✅ | `springdoc-openapi-starter-webmvc-api:2.3.0` |
| com.moyue.account (8081) | Spring MVC | ✅ | 同上 |
| com.moyue.content (8082) | Spring MVC | ✅ | 同上 |
| com.moyue.social (8083) | Spring MVC | ✅ | 同上 |
| com.moyue.commerce (8084) | Spring MVC | ✅ | 同上 |
| com.moyue.search (8085) | Spring MVC | ✅ | 同上 |
| com.moyue.system (8086) | Spring MVC | ✅（已接 UI） | 保留 `webmvc-ui`（内含 api），作为聚合页 |
| com.moyue.message (8087) | Spring MVC | ✅ | `webmvc-api` |
| com.moyue.risk (8089) | Spring MVC | ✅ | `webmvc-api` |
| com.moyue.ai (8097) | Spring MVC | ✅ | `webmvc-api` |
| **单体入口（原 moyue-gateway） (8080)** | **WebFlux** | ❌ **不接** | —— |

**理由：**
1. `单体入口（原 moyue-gateway）` 是 **Spring Cloud（单体已移除） Gateway（WebFlux）**，若接 springdoc 必须改用 `springdoc-openapi-starter-webflux-api` 并在网关起 swagger-ui；但网关本身只做路由转发、没有自有业务 REST，产出文档无价值，且 webflux starter 与现有 WebMVC 体系风格割裂。
2. 各业务服务经 Nacos（单体已移除） 注册、由网关统一路由，真正的 REST 契约都在业务服务侧。把文档源放在业务服务、在 `com.moyue.system` 一处聚合，职责清晰、与"禁用 Docker / 原生部署"的运维模型一致。
3. 因此：**业务服务只引入 `webmvc-api`（轻量、无 UI）自动产出 `/v3/api-docs`；只有 `com.moyue.system` 保留 `webmvc-ui` 作为统一文档门户。**

## 2. 避免 10 份重复配置：可复用自动配置（核心）

在 `com.moyue.common-core` 中建立一次自动配置，所有依赖 `com.moyue.common-core` 的 MVC 业务模块**自动获得**统一的 OpenAPI 元信息（title/version/servers）与 bearer-JWT 安全方案。

### 2.1 文件清单（新增）

```
com.moyue.common/com.moyue.common-core/
├─ pom.xml                                              # 增 optional 依赖 +（根 POM 已管版本）
├─ src/main/java/com/moyue/common/core/openapi/
│  ├─ MoyueOpenApiAutoConfiguration.java                # @AutoConfiguration + OpenAPI @Bean（草图见 §2.3）
│  └─ MoyueOpenApiProperties.java                       # @ConfigurationProperties
```

### 2.5 `MoyueOpenApiAutoConfiguration.java`（草图，守卫是关键）

```java
@AutoConfiguration
@ConditionalOnWebApplication(type = Type.SERVLET)                       // ① WebFlux 网关不激活
@ConditionalOnClass(name = "io.swagger.v3.oas.models.OpenAPI")          // ② 未引 springdoc 不激活（防 NoClassDefFound）
@ConditionalOnProperty(name = "moyue.openapi.enabled", havingValue = "true", matchIfMissing = true)
@EnableConfigurationProperties(MoyueOpenApiProperties.class)
public class MoyueOpenApiAutoConfiguration {

    @Bean
    public OpenAPI moyueOpenAPI(MoyueOpenApiProperties props,
                                Environment env) {
        String name = env.getRequiredProperty("spring.application.name");
        String ver  = props.getVersion() != null ? props.getVersion()
                                                 : env.getProperty("info.app.version", "1.0.0-SNAPSHOT");
        String server = props.getServerUrl() != null ? props.getServerUrl()
                                                     : "http://localhost:" + env.getProperty("server.port", "8080");
        return new OpenAPI()
            .info(new Info()
                .title(props.getTitle() != null ? props.getTitle() : name)
                .version(ver)
                .description(props.getDescription()))
            .servers(List.of(new Server().url(server).description(name)))
            .components(new Components().addSecuritySchemes("bearerAuth",
                new SecurityScheme()
                    .type(SecurityScheme.Type.HTTP)
                    .scheme("bearer").bearerFormat("JWT")))
            .addSecurityItem(new SecurityRequirement().addList("bearerAuth")); // 全局要求 JWT
    }

    /** 可选：按 /api/v1/** 分组，便于前端按域查看；不加也行 */
    @Bean
    @ConditionalOnProperty(name = "moyue.openapi.group", havingValue = "true", matchIfMissing = false)
    public GroupedOpenApi moyueGroupedApi() {
        return GroupedOpenApi.builder().group("moyue").pathsToMatch("/api/v1/**").build();
    }
}
```

## 3. 中央文档聚合（com.moyue.system 聚合 + 优先走网关）

### 3.1 设计原则：swagger-ui 与所有 spec 同源（避免 CORS）

让 `com.moyue.system` 的 swagger-ui 经 **网关** 提供（浏览器全程只访问 8080），urls 用**相对路径**，从而：
- 浏览器 → `http://localhost:8080/api/v1/docs/system/swagger-ui.html`（拿页面）
- 页面内 urls 相对解析 → `http://localhost:8080/api/v1/docs/<svc>/v3/api-docs`（同源拉取）

完全规避跨域。dev 内部使用，并把 docs 路径加入网关 JWT 白名单（prod 由 `SPRINGDOC_ENABLED=false` 整体关闭）。

## 4. 前端代码生成（openapi-generator 接入）

### 4.1 二选一结论：主推 **Maven 插件方案（新增 `moyue-contract` 模块）**

| 方案 | 形态 | 优点 | 缺点 |
|---|---|---|---|
| **(主) Maven 插件** | 新增 `moyue-contract` 模块，`openapi-generator-maven-plugin` 绑定 `generate-sources`，输入可为**活集群 URL** 或**提交的静态 spec 文件** | 纯后端团队、CI 统一、可用静态 sample 验证、**不依赖活集群**；产物直接落到 `moyue-frontend/src/api/` | 需要 Java 侧触发 |
| (备选) npm CLI | `moyue-frontend/package.json` devDependency `openapi-generator-cli` + 脚本遍历各服务 URL | 前端同学熟悉、独立运行 | 需 Node 环境；验证仍需活集群或先 curl 下 spec 落盘 |

> 选择 Maven 插件的核心原因：任务硬性约束"dev 不保证集群在运行"，Maven 插件支持 `inputSpec` 指向**已提交的静态 sample spec**，可在 `mvn generate-sources` 阶段独立跑通整条生成链路，满足"无活集群验证"。前端脚手架仍按 §4.4 建立以接收产物。

### 4.2 `moyue-contract` 模块结构

```
moyue-contract/
├─ pom.xml
├─ specs/                                  # 提交的静态 spec（活集群不可用时退化为这些）
│  ├─ sample-system.json                   # 验证链路用的 sample（见 §4.5 / docs/openapi/sample-system.json）
│  ├─ system.json  account.json ...        # （可选）各服务导出存档
└─ README.md
```

### 4.3 `moyue-contract/pom.xml` 关键片段（草图）

```xml
<dependencies>
    <!-- 仅用于触发插件，无业务代码 -->
</dependencies>

<build>
  <plugins>
    <!-- 验证链路：用提交的 sample spec 证明生成器可用（无需活集群）-->
    <plugin>
      <groupId>org.openapitools</groupId>
      <artifactId>openapi-generator-maven-plugin</artifactId>
      <version>7.7.0</version>
      <executions>
        <execution>
          <id>gen-sample</id>
          <phase>generate-sources</phase>
          <goals><goal>generate</goal></goals>
          <configuration>
            <inputSpec>${project.basedir}/specs/sample-system.json</inputSpec>
            <generatorName>typescript-axios</generatorName>
            <output>${project.basedir}/../moyue-frontend/src/api/sample</output>
            <apiPackage>api</apiPackage>
            <modelPackage>model</modelPackage>
            <additionalProperties>
              <supportsES6>true</supportsES6>
              <withSeparateModelsAndApi>true</withSeparateModelsAndApi>
            </additionalProperties>
          </configuration>
        </execution>
      </executions>
    </plugin>
  </plugins>
</build>
```

> 各服务"活集群"生成：另加 execution，把 `<inputSpec>` 换成 `<url>http://localhost:8081/v3/api-docs</url>`（配合网关聚合也可写 `http://localhost:8080/api/v1/docs/account/v3/api-docs`）。活集群可用时一条命令 `mvn -pl moyue-contract generate-sources` 全量生成；不可用时用 sample 验证链路。

### 4.4 `moyue-frontend/` 脚手架文件清单

| 文件 | 说明 |
|---|---|
| `package.json` | 含 `axios` 运行时依赖；`scripts.gen` 指向 `moyue-contract` 或 openapi-generator-cli |
| `tsconfig.json` | 标准 TS 配置 |
| `src/api/.gitkeep` | 生成产物目录（由插件写入 `<service>/` 子目录） |
| `README.md` | 说明生成命令、如何 import 生成的 client |
| `.gitignore` | 忽略 `node_modules` |

约定产物布局：`moyue-frontend/src/api/<service>/`（如 `src/api/account/`、`src/api/system/`、`src/api/sample/`）。

### 4.5 验证路径（满足"无活集群"约束）

1. 提交 `docs/openapi/sample-system.json`（一份**真实、合法**的 OpenAPI 3.0 契约，字段取自 `com.moyue.system` 真实端点，如 `RewardController` 的 `/api/v1/rewards`、`/rewards/{orderNo}/pay`、`/rewards/income` 等）。
2. 复制到 `moyue-contract/specs/sample-system.json`。
3. 执行：`mvn -pl moyue-contract generate-sources`。
4. 断言：在 `moyue-frontend/src/api/sample/` 生成 `api/*.ts`（含 `RewardApi`、`DefaultApi` 等）、`model/*.ts`、`index.ts`、`runtime.ts`、`README.md` → **证明生成链路可用，零集群依赖**。
5. 活集群就绪后，把 sample execution 切换为各服务 `<url>` 即可批量产出生产客户端。

## 6. 风险与备注

- **网关同源方案依赖 `RewritePath` 与白名单**：若 dev 仍想直连各服务端口看 UI，可退化为 §3.5 备用方式（单服务 `/swagger-ui.html`），聚合页 urls 改用绝对 `http://localhost:<port>/v3/api-docs` —— 但需各服务/网关放开 CORS，故主推同源网关方案。
- **`GroupedOpenApi` 可选**：默认单 group 即可；若某服务接口过多需要分组再加 §2.5 第二个 @Bean。
- **安全方案**：自动配置已声明 `bearerAuth` 且全局 `@SecurityRequirement`。若希望"仅标注接口需要 JWT、公开接口（如登录）不要求"，去掉 `@addSecurityItem` 全局项，改为在对应 Controller/方法用 `@io.swagger.v3.oas.annotations.security.SecurityRequirement(name = "bearerAuth")` 局部标注（推荐，更贴近网关白名单语义）。
- **版本对齐**：所有 springdoc 统一锁 `2.3.0`（与 system 现版本一致），经根 POM `dependencyManagement` 强制，杜绝 2.x 内部漂移。
