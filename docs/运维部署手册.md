# 运维部署手册（墨阅小说网 · moyue-parent）

> 适用版本：P0/P1 全部落地后（P1-1 `f1ba0d6`、P1-2 `e6b4b81`、P1-4 `d9c4f03`、P1-5 `90ec58c`，2026-09-16）
> 面向对象：运维 / SRE / 部署负责人
> 核心原则：**配置驱动优雅降级** —— 外部依赖（LLM / 短信 / 推送 / ES）缺密钥或不可用时自动降级，绝不阻断主链路。
>
> ⚠️ **单体化说明**：本文档写于微服务时期；单体化后整个后端为单个 `moyue-app` 进程（:8080），已移除 Nacos / Gateway / OpenFeign。涉及「各模块 / Nacos / 网关」的措辞以本手册 §5.1、§6 的修正为准。

---

## 1. 四项 P1 能力的降级总览

| 能力 | 模块 | 缺依赖时的行为 |
|---|---|---|
| P1-1 AI 客服 LLM 真实化 | `moyue-ai` | `moyue.ai.llm.enabled=false`/无 `apiKey` → 降级到关键词引擎；网关异常 → 每轮 warn 后降级 |
| P1-2 触达渠道补全 | `moyue-message` | 短信/推送未启用 → `pending`（不投不失败）；邮件未配 `spring.mail` → `failure` |
| P1-4 / P1-5 检索 & RAG | `moyue-search` | ES 不可用 → RAG 召回 warn 降级，对话照常；检索接口异常 → 全局 40001 |

**统一约定**：所有外部密钥（LLM apiKey、短信 accessKey/secret、推送 serverKey、邮件口令）**仅用于鉴权头，绝不打印日志**。

## 2. 环境准备（禁用 Docker）

> 硬性约束（见 `docs/不可忽视条件.md`）：**项目全面禁用 Docker**，基础设施一律原生安装；数据库集成测试用 H2（见 §5）。

| 组件 | 版本/要求 | 说明 |
|---|---|---|
| JDK | 17+ | 各模块 Spring Boot 3.x |
| Maven | 3.9.16（工作区 `tools/apache-maven-3.9.16`） | **用 `mvn.cmd`，不是 `mvn`**（本环境缺 coreutils，sh 脚本会因缺失 `dirname`/`uname` 失败） |
| MySQL | 8.x | 主库，Flyway 自动迁移 |
| Elasticsearch | 8.x + IK 分词 | RAG 与站内检索依赖；本机未启动时需手动起 |
| Nacos | 可选 | 服务注册与配置中心（配置可经 Nacos 覆盖 yml） |

## 3. 配置项总表

### 3.1 AI 客服（moyue-ai）· 前缀 `moyue.ai.llm`
| 配置项 | 默认 | 说明 |
|---|---|---|
| `enabled` | `false` | 是否真实调用大模型；false→降级关键词引擎 |
| `endpoint` | `https://api.openai.com/v1/chat/completions` | OpenAI 兼容网关地址 |
| `apiKey` | 空 | Bearer 鉴权；空→降级 |
| `model` | `gpt-4o-mini` | 模型名 |
| `timeoutSeconds` | `10` | 网关超时 |
| `maxHistory` | `10` | 注入历史轮次 |
| `systemPrompt` | 小墨人设话术 | 可调，无需改代码 |

### 3.2 触达渠道（moyue-message）
**短信 · 前缀 `moyue.sms`**（默认降级 `pending`）
| 配置项 | 默认 | 说明 |
|---|---|---|
| `enabled` | `false` | false→pending 不投 |
| `endpoint` | 空 | 供应商网关（POST JSON） |
| `accessKey` | 空 | Bearer / 签名派生源 |
| `secret` | 空 | 签名派生，不打印 |
| `signName` | 空 | 短信签名 |
| `templateId` | 空 | 默认模板 ID（DTO 可覆盖） |

**推送 · 前缀 `moyue.push`**（默认降级 `pending`）
| 配置项 | 默认 | 说明 |
|---|---|---|
| `enabled` | `false` | false→pending 不投 |
| `endpoint` | 空 | 推送网关（FCM/APNS/厂商通道） |
| `serverKey` | 空 | Bearer 鉴权 |
| `platform` | 空 | 平台标识（FCM/APNS/HUAWEI/…） |

**邮件 · 前缀 `moyue.mail` + `spring.mail.*`**（真实 SMTP，无开关）
| 配置项 | 默认 | 说明 |
|---|---|---|
| `moyue.mail.host` / `port` / `username` / `password` | dev 指向 MailHog `localhost:1025` | 镜像 `spring.mail.*` |
| `moyue.mail.from` | 空 | 默认发件人 |
| `spring.mail.host/port/username/password` | 同上 | JavaMailSender 实际连接参数 |

> 邮件与其他渠道不同：**无 `enabled` 开关**，依赖 `spring.mail` 配置；`JavaMailSender` 未就绪时返回 `failure`（非 pending）。收件人优先级：`targetEmail` → 经 `UserClient` 解析 `user.email` → 均无则 `pending`。

### 3.3 检索 / RAG（moyue-search）· 前缀 `moyue.search`
| 配置项 | 默认 | 说明 |
|---|---|---|
| `indexName` | `moyue_book` | 书籍索引名 |
| `defaultPageSize` | `20` | 默认分页 |
| `ragTopK` | `3` | RAG 召回片段数 |
| `synonyms` | 内置同义词集 | 可被 yml 整体覆盖 |
| `spellDictionary` | 内置纠错词典 | 可被 yml 整体覆盖 |

ES 连接配置（Spring Data Elasticsearch）由 `spring.elasticsearch.*` / `spring.data.elasticsearch.*` 提供，不在代码中硬编码。

## 4. 数据库迁移（Flyway）

新增迁移 `V18__user_contact.sql`（P1-2）：为 `user` 表补充联系字段 `email`、`device_token`（皆为可空）。

- **幂等**：经 `information_schema` 判断列是否存在，再用 `PREPARE/EXECUTE` 动态 `ALTER`，重跑/回退后不会报 `Duplicate column`。
- **H2 测试库不直喂本脚本**：由 `tools/gen-h2-schema.py` 生成等价 schema 到各模块 `src/test/resources/db/h2/`（H2 索引名全局唯一，Flyway 脚本不能直接喂 H2）。
- 迁移顺序：已占用 V1–V17，P1-2 顺延为 **V18**（非 V16/V17，V17 已被 P1-4 风险看板占用）。

## 6. 部署与启动

- **服务编排**：单体化后为单个 Spring Boot 应用 `moyue-app`，直接监听 **:8080**，所有 `/api/v1/**` 由本进程处理；不再有 Nacos 注册 / 网关路由。
- **启动**：`./scripts/start-all.sh`（原生 MySQL / Redis 就绪即可；ES 可选，未启动时限检索 / RAG 自动降级）。XXL-Job 执行器随进程启动（RPC 9099）。
- **AI 客服链路**：`moyue-app` 内 `ai` 域 →（进程内 Service）`search` 域做 RAG 召回；`search` 依赖 ES。启动顺序建议：MySQL → Redis →（ES）→ 单体应用。
- **索引初始化**：`moyue-app` 启动后确认 `moyue_book` / `moyue_chapter` / `moyue_qa` 索引存在；`moyue-qa` 为空时 RAG 不增强但不阻断（见 §1）。
- **禁用 Docker**：所有中间件原生安装启动，禁止用容器编排。

## 7. 降级与监控

- **触达记录表** `message_channel_record`：每条渠道结果落库，`status` 含义
  - `0` 待发 / pending（渠道未启用、无收件号/令牌）
  - `1` 成功
  - `2` 失败（网关非 2xx / 异常）
  可据此统计各渠道成功率，定位未接入的供应商。
- **日志关键词**
  - `LLM 生成失败，降级到关键字引擎` —— LLM 网关异常
  - `RAG 召回失败` —— search 未注册 / ES 异常
  - `短信网关调用失败` / `推送网关调用失败` / `邮件渠道发送失败` —— 对应渠道外呼异常
- **RAG 验证**：直接调 `moyue-search` 的 `moyue-qa` 检索接口，确认某业务问题能召回相关片段。

## 8. 故障排查

| 现象 | 排查点 |
|---|---|
| AI 一直回关键词话术 | `moyue.ai.llm.enabled` / `apiKey` 是否配置；网关连通性；查 LLM 降级日志 |
| RAG 无效但对话正常 | ES 是否启动、`moyue-qa` 是否有数据；查 RAG 召回日志 |
| 短信/推送永远 pending | `moyue.sms.enabled` / `moyue.push.enabled` 是否为 true，endpoint 是否配 |
| 邮件 failure | `spring.mail` / `moyue.mail` 是否配置，SMTP 是否可达 |
| 构建报 `dirname`/`uname` 相关错 | 误用 `mvn` 而非 `mvn.cmd`，改用 §5.1 命令 |
| 网关路由 404 | 确认已含 `6d8a21b` 逗号 OR 修复；检查路由断言 |
| 迁移报 Duplicate column | 不应发生（V18 幂等）；若仍报，检查 `information_schema` 权限 |
