### 本轮修复的 4 处环境级缺陷（均为实跑暴露，静态检查不可见）

| # | 现象 | 根因 | 处置 |
| --- | --- | --- | --- |
| E-1 | 所有服务启动即失败，`Communications link failure` | 沙箱休眠回收容器（`Exited 255/137`），MySQL/Redis/Nacos 全停 | 新增 `e2e/start-infra.sh` 幂等拉起 + 就绪等待 |
| E-2 | Nacos 启动即退出：`Initial heap size set to a larger value` | 镜像默认 `-Xms1g` 与传入 `JVM_XMX=512m` 冲突 | 显式对齐 `JVM_XMS ≤ JVM_XMX` |
| E-3 | 服务连不上注册中心：`Connection refused /127.0.0.1:9848` | Nacos 2.x 客户端除 8848 还需 **gRPC 9848/9849** | 容器补发 `-p 9848:9848 -p 9849:9849` |
| E-4 | Nacos 启动后被内核杀死（exit 137, `OOMKilled=true`） | cgroup 上限 8GB，10 个服务默认堆各 500–760MB | 服务统一 `-Xmx320m -XX:+UseSerialGC`，容器加 `--memory` 上限 |

> **教训**：E-2/E-3/E-4 三处都是「配置写了 ≠ 运行时成立」。与此前 C-1~C-9 同源——
> 微服务架构的真实风险永远在**第一次真跑**才暴露，静态全绿不能替代端到端验证。
